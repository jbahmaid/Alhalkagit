# منصة ربط الكفاءات المهنية (سند)

منصة لحصر الباحثين عن عمل من أبناء القبيلة/العائلة، وبناء قاعدة بيانات لكفاءاتهم، وربطهم بأصحاب العمل داخل المملكة وخارجها.

## الحالة

- المرحلة 4، الدفعة 1 (الأساس): معتمدة. تشمل الصفحة الرئيسية، والدخول، وتسجيل الباحث مع رمز البريد، ونسيان كلمة المرور، وتغييرها، وحساب المدير الأساسي، وسجل التدقيق.
- المرحلة 4، الدفعة 2 (ملف الباحث والسيرة): معتمدة. معالج "ملفي المهني" بست خطوات (البيانات الشخصية، الدار والفخذ، التواصل، التعليم، الخبرات بعدد غير محدود من المناصب، السيرة الذاتية)، وصفحة "ملفي" للعرض والتعديل، ورفع السيرة واستبدالها وتنزيلها، وتحليلها الآلي عند التفعيل.
- المرحلة 4، الدفعة 3 (أصحاب العمل والفرص والمطابقة وطلبات الاهتمام): معتمدة. تسجيل صاحب العمل وانتظار الاعتماد، ولوحته (الفرص المتاحة، طلبات الاهتمام، التوظيف عبر المنصة)، ونشر الفرص وتعديلها وإغلاقها، وقائمة المهتمين وملف كل مهتم مع رابط السيرة المؤقت. وللباحث: الفرص مرتبة حسب الملاءمة بشارتي "مناسبة" و"مقاربة"، وتفاصيل الفرصة مع "لماذا تظهر لك بهذه الدرجة"، وطلب الاهتمام بموافقة صريحة، و"طلباتي". هوية صاحب العمل لا تصل للباحث في أي شاشة أو استجابة.
- المرحلة 4، الدفعة 4 (منطقة المدير وتصدير Excel): جاهزة للمراجعة. لوحة المدير بالأرقام وآخر العمليات، واعتماد أصحاب العمل (بانتظار الاعتماد، معتمدون، غير معتمدين)، والقوائم المرجعية (إضافة وتعديل وتعطيل دون حذف)، والمستخدمون (بحث وتصفية، تعديل ملف الباحث وإظهار رقم الهوية مع تسجيل الاطلاع، تعديل بيانات صاحب العمل، إيقاف وإعادة تفعيل وحذف، وإضافة مدراء لمدير النظام الأعلى)، وسجل التدقيق للقراءة فقط بالتصفية والصفحات، وإعدادات المطابقة، و"حسابي" لكل مستخدم لتغيير البريد برمز تحقق. التصدير إلى Excel بعد تأكيد كلمة المرور، ويُسجّل في سجل التدقيق.
- بقية الشاشات تأتي في الدفعات القادمة.

## التشغيل على جهازك (ويندوز)

### مرة واحدة فقط

1. ثبّت [Docker Desktop](https://www.docker.com/products/docker-desktop/) وشغّله، وانتظر حتى يظهر أنه يعمل (Engine running).
2. نزّل المشروع:
   - إن كان عندك Git: `git clone <رابط المستودع>`
   - أو من صفحة المستودع: Code ثم Download ZIP، وفكّ الضغط.
3. افتح PowerShell داخل مجلد المشروع. الطريقة: افتح المجلد في مستكشف الملفات، اكتب `powershell` في شريط العنوان، واضغط Enter.

### التشغيل

```
docker compose up --build -d
```

- المرة الأولى تأخذ عدة دقائق لأنها تبني البرامج. المرات التالية أسرع.
- لا تحتاج أي إعدادات أو ملف `.env`، فكل شيء له قيمة افتراضية.
- تأكد أن كل الخدمات تعمل:
  ```
  docker compose ps
  ```
  يجب أن تظهر كلمة `healthy` بجانب كل خدمة. خدمة `minio-init` تعمل مرة واحدة ثم تتوقف، وهذا طبيعي.

### الفتح

| ماذا                                                           | الرابط                |
| -------------------------------------------------------------- | --------------------- |
| المنصة                                                         | http://localhost:3000 |
| صندوق البريد المحلي: كل رسالة ترسلها المنصة، ومنها رموز التحقق | http://localhost:8025 |

لا تخرج أي رسالة بريد من جهازك ما دام البريد على الإعداد الافتراضي.

### حساب المدير (أول تشغيل)

- اسم الدخول: `admin`
- كلمة المرور المؤقتة تظهر داخل مربع في سجل الخدمة:
  ```
  docker compose logs api
  ```
- أو اعرضها في أي وقت بهذا الأمر:
  ```
  docker compose exec api cat /app/secrets/admin-initial-password.txt
  ```
- عند أول دخول ستُطلب منك كلمة مرور جديدة. بعد تغييرها يُحذف ملف كلمة المرور المؤقتة.
- هذا "حساب النظام": لا يُحذف ولا يُوقف ولا يتغير دوره. يمكن تغيير بريده من "حسابي" (برمز يصل إلى البريد الجديد) أو من مدير أعلى آخر في شاشة المستخدمين.
- لإضافة مدير: المستخدمون، ثم "إضافة مدير". تصله كلمة مرور مؤقتة بالبريد، ويُطلب منه تغييرها عند أول دخول.
- يمكنك الدخول باسم `admin` أو بالبريد الإلكتروني للمدير (الافتراضي `jbahmaid@gmail.com`، ويمكن تغييره بالمتغير `ADMIN_EMAIL` قبل أول تشغيل).

### نسيت كلمة مرور المدير؟

1. أنشئ ملفاً اسمه `.env` بجانب `docker-compose.yml`، واكتب فيه سطراً واحداً:
   ```
   ADMIN_RESET_PASSWORD=true
   ```
2. شغّل `docker compose up -d`، ثم خذ كلمة المرور المؤقتة الجديدة بالأمر السابق.
3. احذف السطر من `.env` (أو اجعله `false`) حتى لا تتغير كلمة المرور في كل تشغيل.

### الإيقاف وإعادة التشغيل

| الأمر                          | ماذا يفعل                                                                  |
| ------------------------------ | -------------------------------------------------------------------------- |
| `docker compose stop`          | يوقف المنصة، والبيانات محفوظة                                              |
| `docker compose up -d`         | يشغلها من جديد                                                             |
| `docker compose up --build -d` | يشغلها بعد تحديث الكود                                                     |
| `docker compose down`          | يوقفها ويحذف الحاويات، والبيانات محفوظة                                    |
| `docker compose down -v`       | **يحذف كل البيانات** ويبدأ من الصفر: حسابات، سجل، مفاتيح، كلمة مرور المدير |

### الفتح من جوال أو جهاز آخر في نفس الشبكة

1. اعرف عنوان جهازك: اكتب `ipconfig` في PowerShell، وخذ قيمة `IPv4 Address` (مثل `192.168.1.20`).
2. افتح من الجهاز الآخر: `http://192.168.1.20:3000`
3. حتى تعمل روابط البريد بهذا العنوان، أضف إلى `.env`:
   ```
   PUBLIC_URL=http://192.168.1.20:3000
   ```
   ثم شغّل `docker compose up -d`.
4. إن لم تفتح الصفحة: قد يمنعها جدار حماية ويندوز. اسمح لـ Docker Desktop بالشبكات الخاصة (Private) عندما يسألك ويندوز، أو من: إعدادات ويندوز ← الخصوصية والأمان ← أمن Windows ← جدار الحماية ← السماح لتطبيق عبر جدار الحماية.

### الإعدادات الاختيارية

كل المتغيرات موثقة في [`.env.example`](.env.example). للتعديل انسخه باسم `.env` وغيّر ما تحتاج فقط. أهمها:

- `SMTP_*`: لإرسال بريد حقيقي بدل الصندوق المحلي.
- `SMS_ENABLED` و`CV_ANALYSIS_ENABLED`: معطلة افتراضياً.
- تحليل السير الذاتية: ضع `CV_ANALYSIS_ENABLED=true` و`ANTHROPIC_API_KEY=<مفتاحك>` في `.env` ثم أعد التشغيل. بدون المفتاح يبقى التحليل معطلاً وتظهر بطاقة "متاح عند التفعيل". يُرسل نص السيرة فقط، دون الاسم أو الهوية أو بيانات التواصل المدخلة في الملف.
- ملفات السير تُحفظ في حاوية التخزين الخاصة (`cvs`) ولا تُفتح إلا بروابط موقّعة صالحة 5 دقائق عبر عنوان المنصة نفسه.
- المفاتيح السرية تُولّد تلقائياً في أول تشغيل وتُحفظ داخل Docker (في وحدة التخزين `secrets`). لا تُكتب في المستودع أبداً.

## للمطورين

- المتطلبات: Node.js 22 وnpm.
- البنية: `apps/api` (NestJS + Prisma)، و`apps/web` (Next.js)، و`packages/shared` (أنواع وثوابت مشتركة).
- أوامر مفيدة من جذر المستودع:
  ```
  npm ci
  npm test            # اختبارات الوحدات + فحص الترجمات + الأنواع + lint للواجهة
  npm run test:int    # اختبار تكامل على PostgreSQL (يحتاج PostgreSQL 16، العنوان في TEST_DATABASE_ADMIN_URL)
  npm run build
  ```
- اختبارات المتصفح السريعة على المنصة وهي تعمل: `e2e/batch1-smoke.cjs` و`e2e/batch2-profile.cjs` و`e2e/batch3-jobs.cjs` و`e2e/batch4-admin.cjs` (التعليمات في أول كل ملف).
- التصدير: `POST /api/admin/export/token` بكلمة المرور يعطي رمزاً صالحاً 5 دقائق، ثم `POST /api/admin/export/<full|users|audit>` مع `{"token": "...", "locale": "ar"}` يعيد ملف xlsx. لمدراء النظام فقط.
- المطابقة: الأوزان (القطاع 40، المؤهل 25، الخبرة 25، الكلمات 10) والحدود (مناسبة 70 فأكثر، مقاربة 45 فأكثر) في جدول الإعدادات `settings` بالمفتاحين `matching.weights` و`matching.thresholds`، وتُعدّل من شاشة الإعدادات (مجموع الأوزان 100). يعيد العامل (worker) الحساب بعد تعديل الملف أو الفرصة أو الإعدادات بثوانٍ.
